## 这是什么？

> 🌐 **应用本身也有完整的简体中文界面，不只是这份 README。** 页面、按钮、提示和日期都已译成中文，详见[语言](#-语言)。

**Job Application Tracker**（求职申请追踪器）是一个开源、自托管的 Web 应用，用来管理你的求职。它运行在你自己的电脑上，数据保存在一个由你掌控的文件夹里。它是照着技术岗招聘的真实情况设计的：

- 🧑‍💼 **一位招聘顾问会给你推荐好几个职位。** 记录每一位招聘顾问和每一家猎头公司、他们的联系方式，以及你和他们的每次通话。记下他们推荐的职位，然后逐个投递、标为感兴趣或放弃，还能看到他们替你递交过的每一个职位。
- 🔀 **申请流程环节多，又很乱。** 初筛 → 技术面 → 离线作业 → 终面 → Offer。阶段可以自定义，每次变动都记下时间。
- 📝 **各种细节散落各处。** 通话、面试和职位的笔记，Google Doc 链接，PDF，导出的邮件，还有你实际发出的那一版简历和求职信：全都集中在一处。
- ⏰ **事情常常没了下文。** 首页“今日”按你接下来该做什么来归类：“轮到你”（待读回复、到期的跟进、你的待办）、“即将进行”的事，以及“等待对方”的事，其中也包括停滞的申请。“时间线”展示所有公司、所有联系人发生过的每一件事。
- 📊 **你想知道什么做法有效。** 桑基图展示申请的去向，还有各阶段的转化率和停留时间、直投与猎头的结果对比，以及每位招聘顾问和每家猎头公司的评分卡。

## 🔒 你的数据，只属于你

- **不用 AI。** 不会有任何程序读取、总结、打分或上传你的笔记、简历和邮件。
- **不上云，无需账号。** 它运行在 `localhost` 上。你的数据不会发到我们的任何服务器，也不用注册任何东西。
- **不追踪你。** 没有遥测，也没有统计分析。应用从不发送邮件，从不联系任何人，也从不访问网络。
- **你的文件，开放的格式。** 代码之外的一个文件夹：一个 SQLite 数据库，加上一份纯文本导出（JSON Lines 和 Markdown 笔记），不用这个应用也能读。
- **备份很简单。** 把这个文件夹设为 git 仓库，每次改动都会自动生成快照；`jat push` 会把它推送到你自己的私有远程仓库。也可以直接下载一个 zip 文件。
- **不抓取数据。** 它记录的是**你**投出的申请，不是帮你找职位的搜索引擎。

## ✨ 功能

1.0 版：已可正式使用，正在一次真实的求职中每天使用。另见[更新日志](CHANGELOG.md)、[发布版本](https://github.com/waddington/job-application-tracker/releases)和[用户指南](docs/guide/README.md)（均为英文）。

| | 功能 |
|---|---|
| 📋 | **申请列表**：可搜索（公司、职位、招聘顾问），可筛选（阶段、渠道、猎头公司、“待催问”、已归档） |
| 🗂️ | **看板**：在任意阶段之间拖动申请，常规的下一阶段会高亮显示 |
| 🔁 | **灵活的流程**：可以从任意阶段移到任意阶段（也可以开启 Jira 式的允许流转规则），带时间戳的完整历史，还能撤销 |
| 💬 | **被拒反馈**：移到“未通过”时会问对方说了什么（可选），按你写的原样保存在申请里，之后也能修改；所有反馈都集中在“洞察”的“被拒情况”标签页，最新的在前，还能看出被拒发生在哪一轮之后（“6 次里有 4 次在编程作业之后”） |
| 🧑‍💼 | **招聘顾问 CRM**：猎头公司、招聘顾问、多种联系方式，以及他们推荐过的每一个职位 |
| 🪪 | **联系人页面**：每位联系人一个页面（猎头顾问、企业内部招聘人员、用人经理……），有联系方式、通话、对方提到过的职位、笔记和对方参与的每一份申请；一个邮箱地址或一个 LinkedIn 主页只对应一位联系人，同一个人的两条记录可以一键**合并** |
| 🗑️ | **重命名和删除**公司、职位、猎头公司、联系人和申请（也可以归档） |
| ⚠️ | **重复投递提醒**：在两家猎头公司为你递交同一个职位之前就知道 |
| 📝 | **Markdown 笔记**：可以写在申请、公司、猎头公司和联系人上，也可以写通用笔记；都是真正的 `.md` 文件，用什么编辑器都能改 |
| 🔗 | **链接**：可以加在申请、公司和猎头公司上，比如招聘信息、Google Docs、离线作业的代码仓库，带图标和默认标题 |
| 📎 | **文件和邮件**：把 PDF、图片或导出的邮件（`.eml`）拖到申请、职位、公司、猎头公司或联系人上；邮件会按发送时间出现在时间线上 |
| 📄 | **简历和求职信的版本**：每一个定制版本连同它的文件，每份申请用的是哪个版本，每个版本又用在了哪里 |
| 💻 | **面试轮次和编程作业**：用你自己的话描述的编号轮次（“第 2 轮 · 系统设计测试”）会显示在看板上，还有时间、面试官、准备、复盘、被问到的问题和离线作业说明；可以在申请页面、“面试”页或“今日”页把一轮标为已完成（同时请你写复盘），或标为未进行；可以在申请页面、快速预览、“今日”页或“面试”页给一轮改期，时间线会显示每次改期的原时间和新时间、由谁提出以及原因，轮次上会显示推迟了几天，“洞察”里有统计；还没商定新时间时，可以标为待定新时间，并附上一条约定时间的待办，设定新时间后这条待办会自动勾选完成 |
| 🏠 | **今日**（首页）：“轮到你”（待读回复、待答复的 Offer、“情况如何？”、待定新时间的轮次、待办、跟进、待决定的职位）、“即将进行”和“等待对方”（等待回复、久无进展），上方是数字和按阶段分布的进行中申请；每个页面都有带编号步骤的“使用说明”和**新建申请**按钮 |
| 🕰️ | **时间线**涵盖一切：通话、推荐和放弃的职位、申请、面试和 Offer，可以按天列出，也可以用泳道显示（每个职位、联系人、公司或猎头公司一行），可按时间段、类型或相关对象筛选；每位联系人、每家公司和每家猎头公司的页面上都有**时间线**按钮，打开时已经筛选好 |
| 👀 | **概览**：每份申请都有，显示需要处理的事（以及持续了多久）、即将进行的事，以及“3 周前”这样的关键日期 |
| ✅ | **待办**：用你自己的话写（“对方发消息了，记得回”），可以单独存在，也可以关联到某位联系人、公司、猎头公司、职位或申请，日期可选；在“今日”页和它关联的页面上都能看到，做完勾选即可（可撤销） |
| 🤔 | **待决定的职位**：在通话中添加招聘顾问提到的职位，然后投递（通过对方创建申请）、标为感兴趣（先记录，暂不投递），或者放弃并写下理由；每个职位都有自己的页面，带待办、笔记、链接和文件（职位描述会带到申请里） |
| 📞 | **通话与会面**：和联系人的通话与会面，不必属于某一份申请；约一次和招聘顾问的沟通，带上议程，之后记下聊得怎么样；改期时可以记下由谁提出、为什么，也可以标为待定新时间，并附上一条约定时间的待办；会显示在“今日”页和时间线上 |
| 📨 | **等待回复**：标记你已回复，看看该催问谁；**对方已回复**会把它放到“今日”页最上面；**已催问**、**已失联**或**不感兴趣**都只需点一下，曾对你失联的人，名字旁会显示一个幽灵图标；给喜欢的招聘顾问加星标；还能看到每个人*通常*几个工作日内回复 |
| 😴 | **一键催问**：直接在“今日”页设置跟进提醒、延后，或标为已失联 |
| 📊 | **桑基图**展示你的求职漏斗：申请 → 初筛 → 面试 → Offer，可按日期范围和渠道筛选，悬停显示数字；打开面试轮次后，可以看到第 1 轮 → 第 2 轮 → 未通过 |
| 📈 | **洞察**：全貌（每个职位从来源一直到它在各阶段仍在等待的部分）、各阶段转化率、阶段停留时间中位数、直投与猎头的结果对比，以及每周动态 |

## 🚀 快速上手

> 📖 下面的内容，**[用户指南](docs/guide/README.md)**（英文）里都有更详细的说明：数据存放在哪里、应用怎样找到它，备份和恢复，在第二台电脑上使用，自定义阶段，每一条命令，以及常见问题排查。

它可以在 **Windows、Linux 或 macOS** 上运行。你需要 Python 3.12 到 3.14 和 [uv](https://docs.astral.sh/uv/)，以及用来构建网页界面的 Node.js 22.12+ 和 [pnpm](https://pnpm.io/)。装好这些之后，大约十分钟就能完成设置。

```bash
git clone https://github.com/waddington/job-application-tracker.git
cd job-application-tracker
uv sync
pnpm --dir frontend install && pnpm --dir frontend build
```

**用演示数据试一试**（虚构的公司和人物）：

在 Linux 和 macOS 上：

```bash
uv run python scripts/seed_demo.py /tmp/jat-demo    # 需要一个新的或空的文件夹
uv run jat --data-dir /tmp/jat-demo serve          # → http://127.0.0.1:8770
```

在 Windows 上 (PowerShell)：

```powershell
uv run python scripts/seed_demo.py "$env:TEMP\jat-demo"
uv run jat --data-dir "$env:TEMP\jat-demo" serve
```

想要中文的演示数据，就加上 `--lang zh-CN`（同样需要一个新的或空的文件夹）：`uv run python scripts/seed_demo.py --lang zh-CN /tmp/jat-demo-zh`，然后用 `--data-dir /tmp/jat-demo-zh` 启动。

**正式使用。** 你的数据放在单独的文件夹里，与代码分开。把它设为私有 git 仓库，每一批改动完成后，应用都会提交一份可读的快照，你就能免费获得完整历史和备份。

在 Linux 和 macOS 上：

```bash
mkdir -p ~/job-search-data && git -C ~/job-search-data init
git -C ~/job-search-data remote add origin <your-private-repo-url>   # 可选，用于 jat push
cp .env.example .env        # 然后设置 JAT_DATA_DIR=~/job-search-data（或者每次都传 --data-dir）
uv run jat init
uv run jat serve            # → http://127.0.0.1:8770（保持运行）
```

在 Windows 上 (PowerShell)：

```powershell
git init "$HOME\job-search-data"
git -C "$HOME\job-search-data" remote add origin <your-private-repo-url>   # 可选，用于 jat push
Copy-Item .env.example .env # 然后在 .env 中设置 JAT_DATA_DIR
uv run jat init
uv run jat serve            # → http://127.0.0.1:8770（保持运行）
```

在 Windows 上，建议将数据文件夹放在 OneDrive 之外（例如 `C:\Users\<you>\job-search-data`），以避免同步期间发生文件锁定问题。

之后在另一个终端里运行 `uv run jat push`，就会把快照推送到你的私有远程仓库（从不强制推送）。请在仓库根目录运行 `jat`，它会在那里读取 `.env`。数据位置没有设置页面：只能用 `--data-dir` 或 `JAT_DATA_DIR` 指定（[详情](docs/guide/your-data.md#how-the-app-finds-your-data)，英文）。

服务器默认只监听 `127.0.0.1`。`uv run jat --help` 会列出其他命令（`archive`、`export`、`restore`、`snapshot`、`migrate`、`info`）。

## ❓ 常见问题

**免费吗？** 免费。它以 Apache-2.0 许可证开源。

**我的数据存在哪里？** 存在你自己电脑上、由你选定的一个目录里，与代码分开。不会上传到任何地方。

**它用 AI 吗？** 不用。它不会调用任何 AI 服务，也不会把你的数据发送到任何地方。

**能在 Windows 上运行吗？** 可以：它支持 Windows、Linux 和 macOS。在 Windows 上，使用侧边栏的“下载备份”（或 jat archive）来备份你的数据；git 快照目前适用于 Linux 和 macOS。

**它会抓取 LinkedIn 或招聘网站吗？** 不会。它的设计就是记录你投出的申请，不会替你搜索职位。

**非软件类的工作也能用吗？** 能。它是照着技术岗招聘设计的（招聘顾问、编程面试、离线作业），但阶段可以自定义，见[自定义](docs/guide/customising.md)（英文）。

**我的数据是什么格式？** 一个 SQLite 数据库（为了速度），外加一份纯文本导出（每张表一个 JSON Lines 文件），提交到你的数据仓库里。你可以阅读它、diff 它，也可以用 `jat restore` 从它重建数据库。

**怎么备份？** 如果数据文件夹是 git 仓库，备份是自动的：每次改动都会生成快照，`jat push` 会把它推送到你的私有远程仓库。想要一个能随处保存的单个文件，就点侧边栏里的“下载备份”（或运行 `jat archive`）：得到一个包含你的数据、笔记和文件的 zip。解压后对这个文件夹运行 `jat init`，一切就都回来了。见[你的数据](docs/guide/your-data.md)（英文）。

**能在两台电脑上用吗？** 能，但同一时间只用一台：在第二台电脑上克隆你的私有数据仓库，把 `JAT_DATA_DIR` 指向它，然后运行 `jat init`。换电脑时，先在一台上 push，再在另一台上 pull 并运行 `jat restore --force`。[分步说明](docs/guide/your-data.md#using-it-on-a-second-computer)（英文）。

**必须先添加公司和招聘顾问，才能添加申请吗？** 不用。点**新建申请**（每个页面的右上角），输入公司、职位、猎头公司和招聘顾问：新出现的都会自动创建。**?** 按钮会带你走一遍日常的使用流程。

**招聘顾问打电话来聊市场行情，没提具体职位，这该记在哪？** 记在对方的页面上：**约通话**（或者记录一次已经进行过的通话）。标为“已进行”后，用**从这次通话添加职位**把对方提到的每个职位加进来。每个职位都会留在“职位”页等你决定：投递、标为感兴趣或放弃。

**能记录我进行到第几轮面试吗？** 能。每份申请都有编号的轮次，用你自己的话描述（“第 2 轮 · 和工程经理聊聊”“第 3 轮 · 系统设计测试”），看板会显示当前这一轮。

**能离线使用吗？** 能。它是一个本地 Web 应用，不依赖任何外部服务；只有你运行 `jat push` 时，它才会连接你自己的 git 远程仓库。

**支持多用户吗？** 不支持。它是给一位求职者用的个人工具，运行在 localhost 上。
